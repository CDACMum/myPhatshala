1 The story

Linux commands, with a twist

Riya's first day on the data team. Her task: put two days of canteen orders into HDFS, check them, merge them into one local file for the accounts team, and clean up. She guesses hdfs dfs -ls, -mkdir, -cat, -rm, and they all work like Linux. Then two surprises. Copying a 403 MB file takes 5.6 seconds, but moving it takes 1.9 seconds, the same as deleting it. And when she deletes a file by mistake, it's simply gone: no trash.

A> hdfs dfs deliberately looks like Linux, so you'll feel at home in a day. But think about where each command works. mv only changes a name in the NameNode's memory, so moving a 403 MB file, or a 4 TB folder, takes the same time: most of those 1.9 seconds were just Java starting up. cp has to read every byte and write it again through a pipeline. R> And the trash? A> HDFS has a trash, but fs.trash.interval is 0 by default, so it's off unless the admins switch it on. On our lab it's off. With it on, -rm moves files to .Trash and you can get them back. Today: the commands you'll use every day, with real outputs, and which ones to be careful with.
2 Definition

The HDFS shell

Formal definition (write this in exams)

The HDFS shell is the command-line client for Hadoop file systems, invoked as hdfs dfs <command> (equivalent to hadoop fs for HDFS paths). Its commands mirror POSIX tools: listing and inspecting (-ls, -du, -df, -count, -stat, -test, -find, -checksum), reading (-cat, -head, -tail, -text), transferring between local and HDFS (-put/-copyFromLocal, -get/-copyToLocal, -getmerge, -moveFromLocal), changing the namespace (-mkdir, -mv, -cp, -rm, -appendToFile, -touchz) and managing attributes (-chmod, -chown, -chgrp, -setrep). Paths may be absolute (/user/…), relative to the user's home /user/<name>, or full URIs (hdfs://namenode/…, file:///…). Generic options such as -D property=value come before the command.

In simple words

hdfs dfs -something is Linux file handling for HDFS: list, copy in, copy out, read, move, delete, change permissions. Commands that only rename or list are instant; commands that move data take time.

LEVELS> The shell at three levels L1> Like a phone's file manager
  • Folders, files, copy, move, delete: the same ideas.
  • Upload (-put) is like sending a photo to the cloud; download (-get) brings it back.
  • Renaming is instant; copying a big video takes time. HDFS behaves the same way.
L2> Everyday patterns
  • Load data: -mkdir -p, then -put (or -put -f to replace).
  • Check: -ls, -du -s -h, -count, -head / -tail.
  • Publish results: jobs write to a temporary folder, then one -mv makes them visible atomically.
  • Export: -getmerge a result folder into one local file for business users.
  • Script checks: hdfs dfs -test -e path && ….
L3> Things to know before you script
  • Each call starts a JVM. For thousands of small operations use the Java API, WebHDFS, or one job, not a loop of shell calls.
  • -cp copies through the client (it reads and writes every byte); for big copies use distcp, which runs as a parallel job.
  • -rm -r on a big folder is fast for you but creates lots of block deletions for DataNodes, done in the background.
  • Trash is per user and client-side policy plus server setting; never rely on it for important data.
  • Globs (*, ?) are expanded by HDFS: quote them so your local shell doesn't expand them first.

4 Step by step

A morning of real commands

All run as user hadoop inside the namenode container of the lab cluster.

  1. Create a folder and upload

    printf 'order_id,item,amount\n2001,chai,15\n2002,dosa,45\n' > day1.csv
printf 'order_id,item,amount\n2003,poha,25\n' > day2.csv
hdfs dfs -mkdir -p /user/hadoop/canteen/raw
hdfs dfs -put day1.csv day2.csv /user/hadoop/canteen/raw/
hdfs dfs -ls /user/hadoop/canteen/raw
    Found 2 items -rw-r--r-- 3 hadoop supergroup 47 2026-10-21 09:38 /user/hadoop/canteen/raw/day1.csv -rw-r--r-- 3 hadoop supergroup 34 2026-10-21 09:38 /user/hadoop/canteen/raw/day2.csv
    Columns: permissions, replication, owner, group, size in bytes, modification time, path. Folders show - instead of a replication factor.

  2. Read and check sizes

    hdfs dfs -cat /user/hadoop/canteen/raw/day1.csv
hdfs dfs -du -h /user/hadoop/data
hdfs dfs -du -s -h /user/hadoop/data
hdfs dfs -df -h /
hdfs dfs -count -v -h /user/hadoop
    order_id,item,amount 2001,chai,15 2002,dosa,45 4.5 M 13.4 M /user/hadoop/data/canteen_1mb.csv 4.5 M 13.4 M /user/hadoop/data/canteen_orders.csv 134.2 M 402.7 M /user/hadoop/data/orders_x30.csv 402.7 M 1.2 G /user/hadoop/data/orders_x90.csv 402.7 M 1.2 G /user/hadoop/data/orders_x90b.csv 948.6 M 2.8 G /user/hadoop/data Filesystem Size Used Available Use% hdfs://namenode 1007.9 G 2.8 G 66.8 G 0% DIR_COUNT FILE_COUNT CONTENT_SIZE PATHNAME 13 11 958.1 M /user/hadoop
    -du: the first column is the data size, the second the raw disk used with 3 replicas (4.5 M × 3 = 13.4 M). -df is the whole file system. -count -v adds a header.

  3. Copy, rename, append, merge

    hdfs dfs -cp /user/hadoop/canteen/raw/day1.csv /user/hadoop/canteen/day1_copy.csv
hdfs dfs -mv /user/hadoop/canteen/day1_copy.csv /user/hadoop/canteen/day1_backup.csv
hdfs dfs -appendToFile day2.csv /user/hadoop/canteen/day1_backup.csv
hdfs dfs -cat /user/hadoop/canteen/day1_backup.csv
hdfs dfs -getmerge /user/hadoop/canteen/raw merged.csv && cat merged.csv
    order_id,item,amount 2001,chai,15 2002,dosa,45 order_id,item,amount 2003,poha,25 order_id,item,amount 2001,chai,15 2002,dosa,45 order_id,item,amount 2003,poha,25
    Both append and getmerge simply concatenate bytes, so the header line appears twice. HDFS knows nothing about CSV headers; that is your program's job.

  4. Permissions, tests and search

    hdfs dfs -chmod 640 /user/hadoop/canteen/raw/day1.csv
hdfs dfs -ls /user/hadoop/canteen/raw
hdfs dfs -test -e /user/hadoop/canteen/raw/day1.csv; echo "exists: $?"
hdfs dfs -test -e /user/hadoop/canteen/raw/day9.csv; echo "exists: $?"
hdfs dfs -find /user/hadoop -name "*.csv"
hdfs dfs -stat "%n %b bytes, replication %r, block %o, modified %y" /user/hadoop/canteen/raw/day1.csv
    -rw-r----- 3 hadoop supergroup 47 2026-10-21 09:38 /user/hadoop/canteen/raw/day1.csv -rw-r--r-- 3 hadoop supergroup 34 2026-10-21 09:38 /user/hadoop/canteen/raw/day2.csv exists: 0 exists: 1 /user/hadoop/canteen/day1_backup.csv /user/hadoop/canteen/raw/day1.csv /user/hadoop/canteen/raw/day2.csv /user/hadoop/data/canteen_1mb.csv /user/hadoop/data/canteen_orders.csv /user/hadoop/data/orders_x30.csv /user/hadoop/data/orders_x90.csv /user/hadoop/data/orders_x90b.csv day1.csv 47 bytes, replication 3, block 134217728, modified 2026-10-21 09:38:04
    -test prints nothing; its exit code (0 = true) is what scripts use. Quote "*.csv" so the pattern reaches HDFS.

  5. Delete: trash off, then on

    hdfs getconf -confKey fs.trash.interval
hdfs dfs -rm /user/hadoop/canteen/day1_backup.csv
hdfs dfs -ls /user/hadoop/.Trash/Current/user/hadoop/canteen
hdfs dfs -D fs.trash.interval=1440 -rm /user/hadoop/canteen/raw/day2.csv
hdfs dfs -mv /user/hadoop/.Trash/Current/user/hadoop/canteen/raw/day2.csv /user/hadoop/canteen/raw/
    0 Deleted /user/hadoop/canteen/day1_backup.csv ls: `/user/hadoop/.Trash/Current/user/hadoop/canteen': No such file or directory INFO TrashPolicyDefault:196 - Moved: 'hdfs://namenode/user/hadoop/canteen/raw/day2.csv' to trash at: hdfs://namenode/user/hadoop/.Trash/Current/user/hadoop/canteen/raw/day2.csv
    With trash off (0), “Deleted” means gone. With trash on, the file moves to .Trash/Current under the same path, and a -mv restores it. Real clusters usually set fs.trash.interval in core-site.xml.

  6. cp vs mv on a 403 MB file

    time hdfs dfs -cp data/orders_x90.csv data/orders_x90_copy.csv
time hdfs dfs -mv data/orders_x90_copy.csv data/orders_x90_moved.csv
time hdfs dfs -rm -skipTrash data/orders_x90_moved.csv
    real 0m5.615s real 0m1.863s Deleted /user/hadoop/data/orders_x90_moved.csv real 0m1.830s
    cp read and rewrote 403 MB (×3 replicas on disk). mv and rm are metadata changes; their time is mostly the JVM starting, and would be the same for 4 TB.

  7. Errors you will meet

    hdfs dfs -ls /user/hadoop/canteen/raw/day9.csv
hdfs dfs -mkdir /user/hadoop/canteen/raw
hdfs dfs -put day1.csv /user/hadoop/canteen/raw/
    ls: `/user/hadoop/canteen/raw/day9.csv': No such file or directory mkdir: `/user/hadoop/canteen/raw': File exists put: `/user/hadoop/canteen/raw/day1.csv': File exists
    Fixes: check the path; use -mkdir -p; use -put -f to overwrite on purpose.
WARN> hdfs dfs -rm -r -skipTrash /some/path cannot be undone. Many teams protect important folders with snapshots (Lesson 7.4) and require trash to be enabled on the cluster.
5 See it happen

Which daemons does each command wake up?

Six commands from Part 4, and the daemons each one involves.

Metadata commands vs data commands 6 steps
What you see
  1. -ls: a listing with permissions, replication, owner, size and time.
  2. -put: uploads two files; silence means success.
  3. -cat: prints the file contents.
  4. -mv of a 403 MB file: under 2 seconds, mostly Java start-up.
  5. -cp of the same file: 5.6 seconds, three times longer.
  6. -rm with trash off: deleted immediately.
Behind the screen
  1. -ls talks only to the NameNode.
  2. -put uses the full write pipeline (Lesson 6.1).
  3. -cat uses the read path (Lesson 6.2).
  4. -mv changes one entry in the namespace: no DataNode is involved.
  5. -cp is a read plus a write of the whole file through the client.
  6. -rm removes the entry at once; DataNodes delete the block files later, when the NameNode tells them in heartbeat replies.
6 Real-world use

The shell at work

1. Atomic publishing with mv

Pipelines write today's results into out/_tmp_2026-10-21 and only then -mv it to out/2026-10-21. Readers never see half-written data, because a rename is instant and all-or-nothing.

Write to tmp→-mv→Visible at once

2. Shell checks in schedulers

Airflow or cron jobs start the next step only if hdfs dfs -test -e input/_SUCCESS returns 0, and alert if -du -s shows an unusually small input.

-test→Exit code→Run or alert

3. Handing results to business users

A job writes part-00000 … part-00099; an analyst runs -getmerge to get one CSV for a spreadsheet (and removes repeated headers first, as we saw).

part files→getmerge→One CSV

4. Trash as a safety net

Most production clusters set fs.trash.interval to a day or more. Support teams regularly restore files from .Trash after accidental deletes, something impossible with the default of 0.

Wrong -rm→.Trash→-mv back

Simplified; organisations differ in tools and policies.
