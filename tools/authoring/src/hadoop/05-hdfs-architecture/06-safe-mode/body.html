1 The story

“Name node is in safe mode”

Kabir restarts the NameNode and, without waiting, uploads a file. HDFS refuses: put: Cannot create file … Name node is in safe mode. He tries again a minute later and it works. Riya does a nastier experiment: she stops all four DataNodes and restarts the NameNode. Now hdfs dfs -ls lists every file with its size, but hdfs dfs -cat fails with Zero blocklocations … Name node is in safe mode. “It knows the files but can't find them?”

A> Remember: after a restart the NameNode knows every file from its fsimage and edits, but not where the blocks are. That map comes only from DataNode block reports. Until enough blocks have been reported, the NameNode protects you: it allows reading the namespace, but no changes, and it won't start re-replicating blocks just because their DataNodes haven't reported yet. K> So it's waiting for the roll call. A> Exactly. When 99.9% of blocks have at least one reported replica, it waits 30 more seconds for the stragglers, then leaves safe mode by itself. With no DataNodes at all, the threshold can never be reached, so it waits for ever, unless an admin forces it out, which you should do only when you understand why it's stuck.
2 Definition

Safe mode

Formal definition (write this in exams)

Safe mode is a read-only state of the NameNode in which the namespace can be read but not modified (no create, delete, rename or append) and no blocks are replicated or deleted. The NameNode enters it automatically at start-up, after loading the fsimage and edit log, while it collects block reports from DataNodes. It leaves automatically when (1) the fraction of blocks that have at least dfs.namenode.replication.min (1) reported replicas reaches dfs.namenode.safemode.threshold-pct (0.999), and (2) the number of live DataNodes reaches dfs.namenode.safemode.min.datanodes (0), followed by an extension period of dfs.namenode.safemode.extension (30,000 ms). Administrators can control it with hdfs dfsadmin -safemode get | enter | leave | wait; manual safe mode (entered with enter) must be left manually.

In simple words

Right after starting, HDFS is in a careful read-only mode until DataNodes have reported almost all blocks. Then it waits 30 seconds more and opens for writing. Admins can also switch it on and off.

Safe mode settings (Hadoop 3.5.0 defaults)

threshold-pct0.999: the NameNode computes the needed count as the whole number part of total × 0.999
extension30,000 ms
min.datanodes0 (“The minimum number of live datanodes is not required”)
replication.min1 replica counts a block as safe
Allowed in safe models, stat, cat/get of blocks already reported, getconf, fsck, saveNamespace
Refusedput, mkdir, rm, mv, setrep, append; no replication or deletion of blocks
LEVELS> Safe mode at three levels L1> The morning roll call
  • The school opens, but the principal doesn't start classes until almost every teacher has signed in.
  • Students can look at the timetable (read the namespace) but no room changes are allowed (no writes).
  • When 99.9% have signed in, she waits a little for latecomers, then rings the bell.
L2> Why it exists
  • Without it, a restarting NameNode would see “no replicas” for every block and immediately order lakhs of copies, then delete them again as reports arrived.
  • It stops clients from writing while the NameNode can't yet choose good DataNodes or confirm space.
  • The 30 s extension avoids leaving the moment the threshold is touched, while a few DataNodes are still reporting.
  • Scripts that start HDFS and then write data should run hdfs dfsadmin -safemode wait first.
L3> Stuck in safe mode: what it tells you
  • Stuck means too many blocks have no reported replica: DataNodes down, disks lost, or a wrong dfs.datanode.data.dir.
  • The threshold uses a whole-number count: with 9 blocks, int(9 × 0.999) = 8, so one missing block is tolerated (we saw exactly this). With 10 lakh blocks, only 1,000 may be missing.
  • -safemode leave lets the cluster work, but files with missing blocks stay unreadable; first bring DataNodes back or accept the loss.
  • Low disk space on the NameNode's metadata disks (dfs.namenode.resource.du.reserved) also puts it into safe mode.
/LEVELS EXAM> “What is safe mode in Hadoop?”: a read-only state of the NameNode at start-up while it receives block reports; no modifications or replication; exits automatically when 99.9% of blocks have the minimum replicas, after a 30 s extension. Commands: hdfs dfsadmin -safemode get|enter|leave|wait.

The four safemode commands

-safemode get

Prints “Safe mode is ON” or “OFF”.

Check

-safemode wait

Waits until it is OFF. Put it in start-up scripts before any writes.

Scripts

-safemode enter

Freeze changes manually (stays until you leave).

Admin

-safemode leave

Force it off. Only after you know why it's on.

Careful
TIP> The NameNode explains itself. The web UI's Overview, or the Safemode field in /jmx, says how many blocks have been reported, how many are needed, and how many seconds are left. Read it before forcing anything.
4 Step by step

Restart the NameNode and watch safe mode

On the Module 5 lab cluster (8 blocks, 4 DataNodes). The NameNode's own explanation is read from its /jmx “Safemode” field.

  1. Read the settings

    for k in dfs.namenode.safemode.threshold-pct dfs.namenode.safemode.extension \
         dfs.namenode.safemode.min.datanodes dfs.namenode.replication.min; do
  echo "$k = $(docker compose exec namenode hdfs getconf -confKey $k)"
done
    dfs.namenode.safemode.threshold-pct = 0.999f dfs.namenode.safemode.extension = 30000 dfs.namenode.safemode.min.datanodes = 0 dfs.namenode.replication.min = 1
    The f in 0.999f just means a floating-point number in the defaults file.

  2. Restart the NameNode with all DataNodes up

    docker restart lab5-namenode-1
# every few seconds:
docker compose exec namenode hdfs dfsadmin -safemode get
    t=5s Call From namenode/172.19.0.3 to namenode:8020 failed on connection exception: java.net.ConnectException: Connection refused t=10s Safe mode is ON | The reported blocks 8 has reached the threshold 0.9990 of total blocks 8. … In safe mode extension. Safe mode will be turned off automatically in 28 seconds. t=15s Safe mode is ON | … Safe mode will be turned off automatically in 23 seconds. t=28s Safe mode is ON | … Safe mode will be turned off automatically in 10 seconds. t=38s Safe mode is ON | … Safe mode will be turned off automatically in 0 seconds. t=43s Safe mode is OFF
    For the first seconds the NameNode isn't even listening yet (loading fsimage and edits). Then the four DataNodes report within moments, the threshold is reached, and the 30 s extension counts down.

  3. Try to write during safe mode

    docker compose exec namenode hdfs dfs -put /tmp/canteen_orders.csv data/during_safemode.csv
    put: Cannot create file/user/hadoop/data/during_safemode.csv._COPYING_. Name node is in safe mode.
    Writes are refused (SafeModeException). put first writes to a temporary ._COPYING_ name, which is what it tried to create.

  4. Restart with no DataNodes at all

    docker stop lab5-datanode-1 lab5-datanode-2 lab5-datanode-3 lab5-datanode-4
docker restart lab5-namenode-1
docker compose exec namenode hdfs dfsadmin -safemode get
docker compose exec namenode hdfs dfs -ls data
docker compose exec namenode hdfs dfs -cat data/canteen_orders.csv
    Safe mode is ON NameNode says: The minimum number of live datanodes is not required. Safe mode will be turned off automatically once the thresholds have been reached. Found 2 items -rw-r--r-- 3 hadoop supergroup 4692009 2026-10-21 06:49 data/canteen_1mb.csv -rw-r--r-- 3 hadoop supergroup 4692009 2026-10-21 06:49 data/canteen_orders.csv cat: Zero blocklocations for /user/hadoop/data/canteen_orders.csv. Name node is in safe mode.
    The namespace is all there (from the fsimage), so ls works. But no block has a known location, so the data can't be read. The threshold can't be reached, so it waits.

  5. Bring the DataNodes back

    docker start lab5-datanode-1 lab5-datanode-2 lab5-datanode-3 lab5-datanode-4
docker compose logs namenode | grep "STATE\*"
    t=13s Safe mode is ON | … Safe mode will be turned off automatically once the thresholds have been reached. t=19s Safe mode is ON | The reported blocks 8 has reached the threshold 0.9990 of total blocks 8. … turned off automatically in 24 seconds. t=37s Safe mode is ON | … turned off automatically in 5 seconds. t=49s Safe mode is OFF INFO StateChange:406 - STATE* Safe mode is OFF INFO StateChange:411 - STATE* Leaving safe mode after 70 secs
    As soon as the DataNodes register and report, the threshold is met, the extension runs, and the NameNode leaves safe mode on its own: 70 s after its start in total.

  6. A missing block: what safe mode does and doesn't catch

    docker compose exec namenode hdfs dfs -D dfs.replication=1 -put /tmp/canteen_orders.csv data/scratch_r1.csv
# its only replica is on lab5-datanode-1: stop it, restart the NameNode
docker stop lab5-datanode-1
docker restart lab5-namenode-1
docker compose logs namenode | grep -A1 "Safe mode ON"
docker compose exec namenode hdfs fsck / | grep -E "MISSING|Missing blocks|Status"
    STATE* Safe mode ON, in safe mode extension. The reported blocks 8 has reached the threshold 0.9990 of total blocks 9. … /user/hadoop/data/scratch_r1.csv: MISSING 1 blocks of total size 4692009 B. Status: CORRUPT Missing blocks: 1
    The threshold is a whole number: int(9 × 0.999) = 8, so 8 of 9 blocks was “enough” and the NameNode left safe mode with a block missing. fsck reports it. Starting datanode-1 again made the file HEALTHY. On a big cluster the threshold is tighter (1,000 missing blocks out of 10 lakh), but safe mode is not a data-integrity check: fsck is.
WARN> Don't make hdfs dfsadmin -safemode leave a habit. If the NameNode is waiting, it is usually waiting for DataNodes that hold real data. Forcing it out turns “not reported yet” into “missing”, and can start unnecessary re-replication.
5 See it happen

A NameNode restart with no DataNodes, then four

Step 4 and step 5 from the real lab, frame by frame.

Safe mode from start to finish 6 steps
What you see
  1. Right after the restart the NameNode is still loading the fsimage and edits; its RPC port isn't open yet.
  2. Now it answers: safe mode is ON. Listing works, because the namespace is loaded.
  3. Reading fails (no block locations yet) and writing is refused.
  4. The DataNodes start, register and send block reports: 8 of 8 blocks reported.
  5. Threshold reached; the 30 s extension counts down.
  6. Safe mode turns off by itself. Reads and writes work again.
Behind the screen
  1. The NameNode rebuilds its namespace from disk. The block map starts empty.
  2. It enters safe mode: the namespace is complete, so metadata reads work.
  3. With 0 of 8 blocks located, it can't serve data and won't allow changes. (8 × 0.999 = 7.99, so 7 blocks would be enough.)
  4. DataNodes register and send their block reports: every block now has known replicas.
  5. The threshold is met; the NameNode waits the 30 s extension for any late reports.
  6. Safe mode ends automatically. Replication monitoring and writes resume.
6 Real-world use

Safe mode at work

1. Start-up scripts that wait

Automation that restarts a cluster and then loads data runs hdfs dfsadmin -safemode wait before the first write, instead of failing with SafeModeException or sleeping for a guessed time.

Start HDFS→safemode wait→Run jobs

2. Diagnosing a stuck restart

When a large cluster stays in safe mode, admins compare reported vs total blocks in the NameNode UI and look for DataNodes that haven't registered (often a failed disk mount or a whole rack still powering up) before deciding anything.

Stuck→Which nodes missing?→Fix, don't force

3. Freezing the namespace for maintenance

Before upgrades or metadata backups, admins enter safe mode so nothing changes, run saveNamespace, copy the metadata, and only then proceed.

safemode enter→saveNamespace + backup→Upgrade

4. When the NameNode's own disk fills

If the disk holding the edit log runs low, the NameNode enters safe mode to avoid corrupting its metadata. Free space on that disk, then leave safe mode.

Metadata disk full→Safe mode→Free space, leave

Simplified; organisations differ in tools and policies.
