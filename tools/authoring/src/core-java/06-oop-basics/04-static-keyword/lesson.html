One interest rate, a thousand accounts

Riya's mini-bank project has an Account class with a balance and a rate field. When the bank changes its rate from 7% to 6.5%, she has to update every single account object, and she misses one.

Sir, every account has its own copy of the rate. When the rate changes, I have to loop over all of them. Does the rate belong to Riya's account or Kabir's account? Neither. It belongs to the bank… to accounts in general. Then make it static double rate. A static field belongs to the class: there is exactly one copy, shared by every object. Change it once with Account.rate = 6.5 and every account sees the new rate immediately.

What does static mean?

Formal definition (write this in exams)

The static keyword marks a member as belonging to the class itself rather than to its instances. A static variable (class variable) has a single copy shared by all objects of the class, created when the class is initialised. A static method (class method) can be called without creating an object, using ClassName.method(); it has no this reference and cannot directly access instance variables or instance methods. A static block runs once, when the class is initialised. static can also be applied to nested classes and used in import static declarations.

In simple words

Normal (instance) members: one per object. Static members: one for the whole class. If the value or behaviour doesn't depend on which object you're talking about, it can be static.

Static blocks run once, at first use

class Config {
    static int gstRate;
    static {
        System.out.println("Config loading...");
        gstRate = 18;
    }
}

public class Main {
    public static void main(String[] args) {
        System.out.println("main starts");
        System.out.println(Config.gstRate);
        System.out.println(Config.gstRate);
    }
}
main starts Config loading... 18 18

“Config loading...” prints only once, and only when Config is first used, not when the program starts. That's class initialisation, which you'll see in detail in Lesson 8.4.

Static state is shared state. A static field that changes (like a counter) is visible to every part of the program and every thread. That's useful, but it makes code harder to test and needs care with threads (Module 12). Prefer constants (static final) and stateless static methods.

Static and instance members working together

  1. Declare which data is shared

    class Account {
    static double rate = 7.0;   // one for all accounts
    static int count = 0;       // how many accounts exist
    double balance;             // one per account
    When the class is initialised, the JVM creates storage for rate and count once, with the class. No object exists yet.

  2. Update the shared counter in the constructor

        Account(double opening) {
        balance = opening;   // this object's field
        count++;             // the class's field
    }
    Each new Account(…) creates a fresh balance inside the new object, but all of them increment the same count.

  3. Instance methods can read static fields

        double yearlyInterest() {
        return balance * rate / 100;   // own balance, shared rate
    }
    Inside an instance method there is a current object (this), and the class is always reachable, so both kinds of member are available.

  4. Static methods have no current object

        static void setRate(double r) {
        rate = r;           // fine: static field
        // balance = 0;     // error: which account's balance?
    }
    A static method runs without this. Writing balance there gives non-static variable balance cannot be referenced from a static context. To use an object's fields, pass the object in as a parameter.

  5. Call static members through the class name

    Account.setRate(6.5);
System.out.println(Account.count + " accounts at " + Account.rate + "%");
    You can write a1.rate, but it hides the fact that the value is shared. IDEs warn about it; use the class name.

Three accounts, one shared rate

Left: the code and what it prints. Right: the objects on the heap, each with its own balance, and the single copy of the static fields kept with the class.

Instance fields vs static fields 6 steps
What you see
  1. The first time the program uses Account, the class is loaded and initialised: rate = 7.0 and count = 0 are set up.
  2. new Account(5000) creates object #1. The constructor sets its balance and increments the shared count to 1.
  3. A second object, #2, with its own balance. The same count becomes 2.
  4. Interest uses each object's own balance and the one shared rate: 5000 × 7% = 350, 12000 × 7% = 840.
  5. Account.setRate(6.5) changes the single static field. No object was touched.
  6. Both accounts now compute with 6.5%: 325 and 780. Nothing was missed, because there was only one rate to change.
Behind the screen
  1. Static fields are stored with the class, not in any object. In HotSpot they live with the class's Class object, created once when the class is initialised.
  2. Object #1 contains only its instance field, balance. The constructor's count++ updates the class's field.
  3. Object #2 also contains just a balance. There's still exactly one count: 2.
  4. yearlyInterest() reads balance from its own object (this) and rate from the class.
  5. A static method runs with no object. It can change static fields; touching balance there would not compile, because the compiler can't know whose balance you mean.
  6. The next calls read the updated rate. This is why settings, counters and constants are made static.

static in real projects

Every Java codebase uses static members, mostly for constants and helper methods. Mutable static state is used more carefully.

{{ANIM2}}

1. Constants for business rules

static final int MAX_SEATS = 72;, static final double GST_RATE = 0.18;. One copy, can't change, readable names instead of magic numbers.

Rule→static final constant→Used everywhere

2. Utility classes

Math, Arrays, Collections, Objects and your own DateUtils or GstUtil: groups of static methods that need no object state.

Input→Util.method(input)→Result

3. Factory methods

List.of(…), Integer.valueOf(…), LocalDate.of(2025, 1, 26). Static methods that create objects, often reusing cached ones.

Values→Type.of(…)→Ready object

4. Counters and loggers

A per-class logger (private static final Logger log = …) and simple ID generators. For counters used by many threads at once, real systems use AtomicLong or a database sequence.

Examples are simplified. Large applications avoid mutable static fields for business data, because frameworks may run several copies of the code and tests need fresh state.

Riya's bank with a shared rate

class Account {
    static double rate = 7.0;
    static int count = 0;
    String owner;
    double balance;

    Account(String owner, double balance) {
        this.owner = owner;
        this.balance = balance;
        count++;
    }

    double yearlyInterest() {
        return balance * rate / 100;
    }

    static void setRate(double newRate) {
        rate = newRate;
    }
}

public class Main {
    public static void main(String[] args) {
        Account a = new Account("Riya", 5000);
        Account b = new Account("Kabir", 12000);
        System.out.println(Account.count + " accounts at " + Account.rate + "%");
        System.out.println(a.owner + ": " + a.yearlyInterest() + ", " + b.owner + ": " + b.yearlyInterest());
        Account.setRate(6.5);
        System.out.println(a.owner + ": " + a.yearlyInterest() + ", " + b.owner + ": " + b.yearlyInterest());
    }
}
2 accounts at 7.0% Riya: 350.0, Kabir: 840.0 Riya: 325.0, Kabir: 780.0

  • count++Runs in every constructor call, always on the same shared field.
  • static void setRateCalled on the class: Account.setRate(6.5). It has no this.

Interview and viva questions

What is the difference between static and instance variables?

An instance variable belongs to an object; every object has its own copy, created by new. A static variable belongs to the class; there is a single copy shared by all objects, created when the class is initialised. Change a static variable through one object and every object sees the change.

Can we access instance members from a static method?

Not directly, because there is no current object. You can if you have a reference: static void print(Account a) { System.out.println(a.balance); }. That's also how main works with objects: it creates them first.

Can static methods be overridden?

No. A subclass can declare a static method with the same signature, but that hides the parent's method; the call is chosen at compile time from the reference type, not at run time from the object. Overriding (Lesson 7.4) applies only to instance methods.

Where are static variables stored?

With the class rather than in any object. In the HotSpot JVM since Java 8, class metadata is in Metaspace and static fields are stored with the class's java.lang.Class object on the heap. For exams, “in the class area, one copy per class” is the expected answer.

What is a static block used for?

One-time setup for the class: initialising static fields that need several statements, filling lookup tables, or loading a native library. It runs once when the class is initialised, before any static method or field of that class is used.

Real-world scenario questions (asked in company interviews)

Interviewers use static to see whether you understand shared state. Decide your answer, then open the model answer.

Food delivery · bug huntFresher

Every cart shows the same items

In a food-ordering app, every user suddenly sees the same cart. The Cart class has static List<String> items = new ArrayList<>();. What's wrong?

The interviewer is checking: do you know that static means one copy for the whole class?

Show a strong answer
  • items is static, so there is one list for all carts. Every user adds to and reads from the same list.
  • Each cart needs its own items: remove static so the list becomes an instance field created per object.
  • On a server, static data is also shared across all requests and threads, which can leak one customer's data to another.

Avoid: “clear the list after each order”. That hides the design error and still mixes concurrent users.

Banking · design1–3 years

Static utility or object?

A team has InterestCalculator with only static methods. Now different products need different rules (savings, FD, senior citizen). How would you evolve it?

The interviewer is checking: do you know the limits of static methods?

Show a strong answer
  • Static methods can't be overridden, so you can't plug in different rules per product.
  • Turn the rule into an interface (InterestRule) with one implementation per product, and pass the right object in (Lessons 7.5–7.7).
  • Keep genuinely stateless helpers static (rounding to paise, for example).

Avoid: adding a growing if-else chain on product type inside a static method.

E-commerce · concurrency1–3 years

Duplicate order numbers

Order IDs come from static int next = 1000; and id = next++; in the constructor. Under sale-day load, two orders got the same ID. Why, and how do you fix it?

The interviewer is checking: can you connect static shared state with thread safety?

Show a strong answer
  • next++ is read, add, write: two threads can read the same value before either writes back (a race condition, Lesson 12.4).
  • Use static final AtomicLong next and next.incrementAndGet(), or a synchronized method.
  • With several servers, an in-memory counter isn't enough at all: use a database sequence or a UUID.

Avoid: saying static fields are “thread-safe because there's only one copy”. One shared copy is exactly the problem.

Testing · code review3+ years

Tests pass alone but fail together

Each test class passes when run alone, but the full test suite fails randomly. The code keeps a static Map cache of discounts that some tests modify. What's going on?

The interviewer is checking: do you understand static state's lifetime?

Show a strong answer
  • Static fields live as long as the class is loaded, usually the whole test run, so one test's changes leak into the next.
  • Make the cache an instance field of a service object created per test, or reset it explicitly in test setup.
  • In production, static caches also need a size limit and an expiry policy.

Avoid: fixing it by forcing a test order.
