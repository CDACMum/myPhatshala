Twenty-five lines for two fields

Riya needs a Dish class with a name and a price. By the time she has written the fields, constructor, getters, equals, hashCode and toString, it's 25 lines, and she forgot to update equals when she added a veg field. Her JSON test data is a wall of \" and +.

Sir, this class only carries two values. Why so much code? Since Java 16 you write record Dish(String name, int price) { } and the compiler generates all of it, and keeps equals in sync forever. Anything for my messy JSON strings? Text blocks. And var for those long generic types. Three small features, a lot less typing.

What are var, records and text blocks?

Formal definition (write this in exams)

var (Java 10) declares a local variable whose static type is inferred by the compiler from its initializer; it is not a keyword for dynamic typing and cannot be used for fields, parameters or variables without an initializer. A record (Java 16) is a restricted, implicitly final class that is a transparent carrier for immutable data: its header declares components, and the compiler generates private final fields, a canonical constructor, accessor methods named after the components, and equals, hashCode and toString based on all components. A text block (Java 15) is a multi-line string literal delimited by """, in which incidental indentation is removed and quotes need no escaping.

In simple words

var: “you know the type, compiler, you write it”. Record: “this is just data; give me the usual methods”. Text block: “keep my text exactly as I typed it”.

What happens at new Order("A1", 500) for a record

  1. The compiler has generated the class

    record Order(String id, int amount) {
    Order { if (amount < 0) throw new IllegalArgumentException(); }
}
    A final class extending java.lang.Record, with fields id and amount, accessors, equals, hashCode and toString.

  2. Allocate the object

    new creates the object on the heap with default field values.

  3. Run the compact constructor

    Your validation runs first, with the parameters id and amount. If it throws, no Order is ever handed out.

  4. Assign the fields

    At the end of the compact constructor the compiler-added code assigns this.id = id; this.amount = amount;. The fields are final: they can never change again.

  5. Use it

    o.amount() reads the field; o.equals(other) compares both components; o.toString() gives Order[id=A1, amount=500].

Modern Java in real projects

New Spring Boot and microservice code uses records for request and response objects, var for locals, and text blocks for queries and templates.

{{ANIM2}}

1. API request/response objects

record CreateOrderRequest(String customerId, List<Item> items): JSON libraries map JSON to records and back.

POST /orders→record CreateOrderRequest→service

2. Query results and SQL

Repository methods return records like record CitySales(String city, long total); the SQL itself sits in a readable text block.

"""SELECT …"""→List<CitySales>→report

3. Value objects

Money, Pincode, PhoneNumber, DateRange: small records with validation in the compact constructor prevent invalid values everywhere.

new Money(-10)→compact constructor→rejected

Email bodies, SMS templates and JSON fixtures for tests are written as text blocks and filled with formatted.

Lesson 14.5 in one screen

  • var: local variables only, initializer required, type fixed at compile time.
  • Record: record Name(Type a, Type b) { }: final, immutable, data-only class.
  • Generated: private final fields, canonical constructor, accessors a(), equals, hashCode, toString.
  • Compact constructor Name { … } validates before fields are set.

Interview and viva questions

Is Java dynamically typed now because of var?

No. The compiler infers the type from the initializer at compile time, and the variable keeps that type forever; assigning a different type is a compile error. var only removes the need to write the type.

What does the compiler generate for a record?

A final class extending java.lang.Record with private final fields for each component, a public canonical constructor, public accessor methods named after the components, and equals, hashCode and toString implementations based on all components. You can add methods, static fields, a compact or custom constructor, and implement interfaces.

Record vs Lombok @Data / a normal class?

Records are a language feature (no library), always immutable and final, with value-based equality. A normal class or Lombok's @Data can have mutable fields, setters and inheritance. Use records for plain data; use classes when an object has changing state or rich behaviour.

Are records completely immutable?

Their fields are final, but if a component is a mutable object (like an ArrayList), its contents can still change. Make defensive copies in the compact constructor, e.g. items = List.copyOf(items);.

How are text blocks different from normal strings?

They span multiple lines, don't need escaped quotes or \n, and strip incidental indentation. At run time they're ordinary String objects; the processing happens at compile time.

{{PRACTICE}}

Real-world scenario questions (asked in company interviews)

Modern-Java questions check whether you use these features where they help, and know their limits.

Bug · equalsFresher

Duplicate products in a HashSet

A Product class with id and name is put into a HashSet to remove duplicates, but duplicates remain. A teammate added a new field last week. How would records help?

The interviewer is checking: equals/hashCode contracts and records.

Show a strong answer
  • The class either never overrode equals/hashCode or they weren't updated with the new field, so equal products look different to the set.
  • Make it record Product(String id, String name, …): equals and hashCode are generated from all components and stay in sync whenever a component is added.
  • If only id should define equality, a record isn't the right fit; keep a class with an explicit equals on id.

Avoid: converting to a record without checking which fields should define equality.

Design · immutabilityJunior

A “record” whose list keeps changing

record Cart(String user, List<Item> items) is shared between threads. Someone calls cart.items().add(item) and another thread sees a half-updated cart. Records are immutable; how did this happen?

The interviewer is checking: shallow immutability.

Show a strong answer
  • The items field can't be reassigned, but the ArrayList it points to is mutable.
  • In a compact constructor: items = List.copyOf(items);, an unmodifiable copy. Adding an item then means creating a new Cart.

Avoid: adding synchronized everywhere instead of making the data truly immutable.

Code review · varJunior

Should we ban var?

Your team lead says “var makes code unreadable, let's ban it”. Another developer uses var for everything, including var result = engine.run(input);. What guideline would you propose?

The interviewer is checking: balanced judgement.

Show a strong answer
  • Use var when the type is obvious from the right side (new, literals, well-named factory methods) or very long; avoid it when the type is unclear from the line.
  • Choose good variable names (var pendingOrders), and keep methods short so inferred types are easy to follow.
  • Never use var to hide a surprising type (e.g. a long vs int in calculations).

Avoid: “always” or “never”.

Security · SQLMid

Text block + formatted + user input

A search API builds SQL with a text block: """SELECT * FROM orders WHERE city = '%s'""".formatted(cityFromUser). It reads nicely. Any concern?

The interviewer is checking: SQL injection awareness.

Show a strong answer
  • Formatting user input into SQL allows injection: ' OR '1'='1 returns every order.
  • Keep the text block for readability, but use ? placeholders and PreparedStatement.setString (or named parameters in your framework).

Avoid: trying to escape quotes yourself.
