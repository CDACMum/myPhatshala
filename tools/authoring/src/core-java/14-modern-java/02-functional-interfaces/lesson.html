Five interfaces called “Checker”

Riya's canteen app now has PriceChecker, StockChecker, CouponChecker, TimeChecker and ItemChecker: five interfaces, each with one method that takes something and returns true or false.

Sir, every lambda needs an interface, so I keep making new ones. Is that how it's done? All five have the same shape: something in, true or false out. Java already has that interface: Predicate<T>. And it can combine rules with and and or, which yours can't. Are there ready-made ones for other shapes? A whole package. Learn four shapes and you'll recognise the rest.

What is a functional interface?

Formal definition (write this in exams)

A functional interface is an interface that has exactly one abstract method (a SAM, “single abstract method”), apart from public methods of Object. It may also have any number of default and static methods. Instances of functional interfaces can be created with lambda expressions, method references or constructor references. The optional annotation @FunctionalInterface makes the compiler verify the rule. The package java.util.function provides general-purpose functional interfaces such as Predicate<T>, Function<T,R>, Consumer<T> and Supplier<T>, plus two-argument and primitive specialisations.

In simple words

A functional interface is a socket with one pin. Any lambda with the right shape plugs in.

How the compiler matches a lambda to an interface

  1. Find the target type

    Predicate<Integer> bigOrder = amt -> amt > 1000;
    The variable's type is Predicate<Integer>.

  2. Find its single abstract method

    boolean test(Integer t). Default methods like and are ignored.

  3. Check the lambda's shape

    One parameter (so amt is an Integer), and the body must produce a boolean: amt > 1000 does. Mismatches are compile errors.

  4. Create the object

    At run time an object implementing Predicate is created; its test runs the lambda body.

  5. Use the extras

    Predicate<Integer> freeDelivery = bigOrder.or(amt -> amt == 0);
    Default methods build new Predicate objects that call the originals. Nothing is tested until you call test.

{{ANIM}}

Functional interfaces in real systems

Libraries and frameworks accept functional interfaces wherever you plug in your own logic.

{{ANIM2}}

1. Validation and rules engines

Eligibility, fraud and coupon rules are written as Predicates and combined, so a new rule is one new line.

loan application→rules.and(...).or(...)→approve / reject

2. Data transformation

Mapping database rows to objects and objects to JSON uses Functions (often method references like Customer::fromRow).

row→Function<Row, Customer>→object

3. Logging and lazy values

Loggers accept a Supplier<String> so an expensive message is only built if that log level is enabled.

log.debug(() -> …)→Supplier.get() only if needed→no wasted work

4. Event listeners

“On payment success”, “on file uploaded” and “on message received” hooks are Consumers registered by different modules.

payment event→Consumer<Payment>s→SMS, email, audit

Simplified: real rules engines also log which rule decided, so decisions can be explained to customers and auditors.

Quick revision

Lesson 14.2 in one screen

  • Functional interface = exactly one abstract method; default/static methods allowed.
  • @FunctionalInterface makes the compiler check it.
  • Predicate test (T→boolean), Function apply (T→R), Consumer accept (T→void), Supplier get (()→T).
  • Bi- versions take two inputs; UnaryOperator/BinaryOperator keep one type; Int-/Long-/Double- versions avoid boxing.
  • Combine: and/or/negate, andThen/compose, Consumer.andThen.
  • Method references: Class::staticMethod, obj::method, Class::instanceMethod, Class::new.

Interview and viva questions

What is a functional interface? Give examples.

An interface with exactly one abstract method, which lambdas and method references can implement. Examples: Runnable (run), Callable (call), Comparator (compare), Predicate (test), Function (apply), Consumer (accept), Supplier (get).

Comparator has equals() too. Why is it still functional?

Abstract methods that match public methods of Object (like equals) don't count, because every implementation already inherits them from Object. Only compare counts.

Difference between Function and UnaryOperator?

UnaryOperator<T> extends Function<T,T>: same input and output type. It's just a more specific, more readable name for that case, e.g. String::trim.

What are the types of method references?

Static method (Math::max), instance method of a particular object (System.out::println), instance method of an arbitrary object of a type (String::length, where the first argument becomes the receiver), and constructor (ArrayList::new).

Why use Supplier for default values?

Laziness: a Supplier only computes its value when get() is called. Methods like Optional.orElseGet(supplier) and logging APIs use this to avoid expensive work that might not be needed.

{{PRACTICE}}

Real-world scenario questions (asked in company interviews)

These check whether you can use the standard interfaces to keep code small and flexible.

Design · rulesJunior

A 200-line if-else for discounts

Discount logic is one giant method with nested ifs for festival offers, first orders, bank cards and city promos. Marketing adds a new rule every week. How would you restructure it with functional interfaces?

The interviewer is checking: rules as data.

Show a strong answer
  • Model each rule as a pair: a Predicate<Order> (does it apply?) and a Function<Order, Discount> (how much?).
  • Keep rules in a list (or load them from config); evaluate them in order or pick the best.
  • Each rule becomes independently testable, and adding one doesn't touch the others.

Avoid: inventing a new interface for every rule type when Predicate and Function fit.

Performance · boxingMid

A hot loop creating millions of Integers

A pricing engine applies Function<Integer,Integer> to 50 million prices a minute. Profiling shows lots of time in garbage collection of Integer objects. What change would you make?

The interviewer is checking: primitive functional interfaces.

Show a strong answer
  • Each apply boxes the int argument and result into Integer objects.
  • Use IntUnaryOperator (or IntFunction, ToIntFunction, IntStream) to stay with primitives.
  • Measure again; primitive streams and arrays usually remove most of the GC pressure.

Avoid: tuning the GC first; remove the allocation.

Logging · performanceJunior

Debug logs slowing down production

log.debug("cart: " + cart.toJson()) runs on every request. Debug logging is off in production, yet the server spends a lot of time in toJson(). Why, and how do you fix it?

The interviewer is checking: lazy evaluation with Supplier.

Show a strong answer
  • The argument string is built before debug is even called, whether or not it's logged.
  • Pass a Supplier<String>: log.debug(() -> "cart: " + cart.toJson()). The logger calls get() only if debug is enabled.

Avoid: deleting the logs; you'll want them when debugging.

API designMid

Should we create our own interface?

A teammate wants to add interface TaxCalculator { BigDecimal calculate(Invoice i); } although Function<Invoice, BigDecimal> has the same shape. Which would you choose?

The interviewer is checking: trade-offs, not dogma.

Show a strong answer
  • For internal, short-lived plumbing, Function is enough and composes with andThen.
  • For a core domain concept used across the codebase, a named interface documents intent, can carry Javadoc, checked exceptions or extra default methods, and avoids mixing up two Functions with the same types.
  • Mark it @FunctionalInterface so lambdas still work.

Avoid: “always” or “never” answers.
