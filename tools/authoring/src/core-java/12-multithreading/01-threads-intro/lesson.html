The app that froze on “Download”

Riya's college-canteen app downloads the menu, today's offers and the dish photos one after another when it opens. On slow campus Wi-Fi the screen stays blank for six seconds, and the Back button doesn't respond.

Sir, each download is only two seconds. Why does the whole app freeze? Because one thread is doing everything: download, download, download, and only then draw the screen. While it waits for the network, nothing else can happen. So I need more threads? Yes. Your program is one process, and inside it you can run several threads at once. They share the same data, but each one follows its own path through the code. Let's see what that really means inside the JVM.

What are processes and threads?

Formal definition (write this in exams)

A process is a program in execution, with its own memory space and system resources, isolated from other processes by the operating system. A thread is the smallest unit of execution that the OS can schedule; it runs inside a process. All threads of a process share its heap memory, loaded classes and open files, but each thread has its own stack (method frames and local variables) and its own program counter. In Java, every program starts with one thread called main, and more threads are represented by java.lang.Thread objects.

In simple words

A process is a restaurant; threads are the cooks in its kitchen. They share the same fridge and stove (the heap), but each cook follows their own recipe card (their own stack).

From java Main to the last thread

  1. The OS starts a process

    Running java Main makes the operating system create a new process with its own memory. The JVM sets up the heap and the method area inside it.

  2. The JVM creates the main thread

    It also starts its own helper threads (garbage collection, JIT compilation). The main thread gets a stack and calls main(args): its first frame.

  3. Your code creates more threads

    Thread t = new Thread(() -> download("menu.json"));
t.start();
    new Thread(…) only creates an object on the heap. start() creates the real thread: a new stack, registered with the scheduler.

  4. The scheduler shares the cores

    The OS decides which thread runs on which core and for how long, switching between them many times a second. You cannot predict the exact order: that's why output from different threads can interleave differently each run.

  5. Threads end; then the JVM exits

    A thread ends when its run code returns. When the last non-daemon thread (often main) ends, the JVM stops any daemon threads and the process exits.

{{ANIM}}

Threads in real systems

Almost every serious Java program uses several threads, even when you don't create them yourself.

{{ANIM2}}

1. Responsive apps

Mobile and desktop apps keep one thread for the screen and push slow work (network calls, files, image processing) to background threads, so the app never looks frozen.

tap “Refresh”→background thread→screen stays smooth

2. Web servers

A server handling bookings or payments serves many customers at once, typically handing each incoming request to a thread from a pool.

1,000 requests→thread pool→answered concurrently

3. Batch jobs that use every core

Month-end jobs (interest for lakhs of accounts, report generation) split the data into chunks and process the chunks in parallel on all cores.

10 lakh accounts→8 threads × chunks→done much sooner

4. Background helpers

Autosave, cache cleanup, metrics reporting and the JVM's own garbage collector run on helper (often daemon) threads while the main work goes on.

every 60 s→daemon thread→draft saved

Examples are simplified. Real apps usually use thread pools and frameworks rather than creating raw threads by hand (Lesson 12.6).

Interview and viva questions

What is the difference between a process and a thread?

A process is a running program with its own isolated memory and resources. A thread is a unit of execution inside a process. Threads of the same process share heap memory and resources, which makes communication easy and creation cheap, but each thread has its own stack and program counter.

What do threads share, and what do they not share?

Shared: heap objects, static fields, loaded classes, open files. Not shared: the stack (method frames, local variables, parameters) and the program counter. That's why local variables are naturally thread-safe and shared objects are not.

What is the difference between concurrency and parallelism?

Concurrency means multiple tasks make progress in overlapping time periods, possibly by taking turns on one core. Parallelism means tasks execute at the same instant on multiple cores. Parallelism is one way to achieve concurrency.

What is a daemon thread?

A low-priority background thread that does not prevent the JVM from exiting. When only daemon threads remain, the JVM shuts down and stops them abruptly. Use setDaemon(true) before start(); never use daemons for work that must complete.

Why can't you predict the order of output from two threads?

The operating system's scheduler decides when each thread runs and for how long, based on load, cores and timing. To get a guaranteed order you must coordinate threads explicitly, for example with join(), locks or queues.

{{PRACTICE}}

Real-world scenario questions (asked in company interviews)

Interviewers use threads questions to see whether you understand what runs where, and what can go wrong.

Mobile app · UXFresher

The app hangs on the payment screen

Users report that after tapping “Pay”, the app becomes unresponsive for 5–8 seconds. The code calls the payment gateway directly inside the button's click handler. What's going on, and what would you change?

The interviewer is checking: that you know the UI runs on one thread and slow work must move off it.

Show a strong answer
  • The click handler runs on the UI thread. A blocking network call there stops the screen from redrawing or reacting.
  • Move the gateway call to a background thread (or a thread pool / async API), show a progress indicator, and update the screen when the result comes back.
  • Disable the Pay button while the call is in flight so the user can't pay twice.

Avoid: “Make the network faster.” The design is the problem, not the speed.

Backend · capacityJunior

One thread per request, 20,000 users

A booking service creates a brand-new thread for every incoming request. During a festival sale traffic jumps to 20,000 concurrent requests and the server runs out of memory. Explain why and suggest a fix.

The interviewer is checking: that threads cost memory and should be pooled.

Show a strong answer
  • Each platform thread reserves its own stack (often hundreds of KB to 1 MB). Thousands of threads use gigabytes and spend time switching.
  • Use a bounded thread pool with a queue (Lesson 12.6), or Java 21 virtual threads for I/O-heavy work.
  • Add back-pressure: reject or queue excess requests instead of crashing.

Avoid: just raising the heap size; stacks aren't even on the heap.

Fintech · data lossJunior

The audit log is sometimes empty

A tool records transactions, and a background thread writes them to an audit file. Sometimes, after the program ends, the last few entries are missing. The background thread was created with setDaemon(true). Why?

The interviewer is checking: JVM exit rules and daemon threads.

Show a strong answer
  • When main ends, only the daemon is left, so the JVM exits immediately and kills it mid-write.
  • Use a normal thread and signal it to finish, then join() it; or use an executor and call shutdown() + awaitTermination().
  • Flush and close the file in the writer (try-with-resources).

Avoid: adding Thread.sleep at the end of main and hoping it's long enough.

Analytics · performanceMid

“We added threads and nothing got faster”

A report job that calculates statistics for 50 lakh rows was changed to use 200 threads on a 4-core server. It got slightly slower. Explain.

The interviewer is checking: CPU-bound vs I/O-bound work and core limits.

Show a strong answer
  • The work is CPU-bound: only 4 threads can actually run at a time. The other 196 just wait, and switching between them adds overhead.
  • For CPU work, use about as many threads as cores (availableProcessors()), each on a chunk of data.
  • Many threads help only when they spend most of their time waiting on I/O.

Avoid: “more threads = more speed.” Measure, and match threads to the kind of work.
