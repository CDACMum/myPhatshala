A bill that knows its shop

Riya is writing billing software for a chain of chai stalls. Every Bill needs the stall's name and GST number on top. She has been passing the Shop object into every bill by hand, and twice she passed the wrong shop.

Sir, every bill needs its shop's name. I keep passing the shop in, and sometimes it's the wrong shop. Then make Bill an inner class of Shop. You create a bill from a shop: shop.new Bill(120). Each bill then remembers its shop automatically and can read the shop's fields, even private ones. And the GST calculation? It doesn't need any particular shop. That's a static nested class: grouped inside Shop for neatness, but with no link to a shop object. And for the festival discount used in just one place, you don't even need a name: an anonymous class, written right where you use it.

What are nested classes?

Formal definition (write this in exams)

A nested class is a class declared inside another class or interface. A static nested class is declared with static and is not tied to an instance of the outer class. A non-static nested class is an inner class; there are three kinds: a member inner class (declared at class level), a local class (declared inside a block such as a method) and an anonymous class (declared and instantiated in a single expression, without a name). Every inner class instance holds an implicit reference to an instance of its enclosing class, and inner classes can access the enclosing class's members, including private ones. Local and anonymous classes may use local variables of the enclosing block only if they are final or effectively final.

In simple words

A class written inside another class. If it's static, it's just stored there. If it isn't, each of its objects belongs to an outer object and can use that object's data. Anonymous classes are quick, nameless classes for one-time use.

1. Member inner class

class Shop {
    private final String name;

    Shop(String name) { this.name = name; }

    class Bill {                                // inner: no 'static'
        int amount;
        Bill(int amount) { this.amount = amount; }

        String print() {
            return name + ": ₹" + amount;       // reads the outer object's private field
        }
    }
}

public class Main {
    public static void main(String[] args) {
        Shop kharghar = new Shop("Chai Point, Kharghar");
        Shop vashi = new Shop("Chai Point, Vashi");

        Shop.Bill b1 = kharghar.new Bill(120);  // a bill OF the Kharghar shop
        Shop.Bill b2 = vashi.new Bill(45);
        System.out.println(b1.print());
        System.out.println(b2.print());
    }
}
Chai Point, Kharghar: ₹120 Chai Point, Vashi: ₹45

class Shop {
    static class Tax {                         // static: no Shop object needed

4. Anonymous class

import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

interface Discount {
    int apply(int price);
}

public class Main {
    public static void main(String[] args) {
        Discount festive = new Discount() {        // class with no name, created at once
            public int apply(int price) {
                return price - price / 10;         // 10% off
            }
        };
        System.out.println(festive.apply(500));

        List<String> names = new ArrayList<>(List.of("Riya", "Kabir", "Om"));
        names.sort(new Comparator<String>() {     // a one-off sort rule
            public int compare(String a, String b) {
                return a.length() - b.length();
            }
        });
        System.out.println(names);
    }
}
450 [Om, Riya, Kabir]

Since Java 8, an anonymous class implementing an interface with a single abstract method is usually written as a lambda: p -> p - p / 10 (Lesson 14.1). Anonymous classes are still needed when you extend a class, implement several methods, or need fields.

Captured variables must be effectively final

int off = 50;
off = 60;                                          // now 'off' changes...
Discount d = new Discount() {
    public int apply(int p) { return p - off; }    // error
};
error: local variables referenced from an inner class must be final or effectively final

The anonymous object copies the value of off into a hidden field (val$off) when it's created. If the local could change later, the copy and the original would disagree, so Java forbids it.

Which one? Start with a static nested class: it's simpler and holds no hidden reference. Make it an inner class only if each object truly needs its outer object. Use anonymous classes (or lambdas) for short, one-place behaviour, and a normal top-level class when other files need it.

What happens on shop.new Bill(120)

  1. javac compiles two classes

    From one Shop.java, javac writes Shop.class and Shop$Bill.class. To the JVM, an inner class is an ordinary class with a $ in its name; Java 11+ records them as “nestmates” so they can share private members.

  2. The constructor gets an extra argument

    Shop.Bill b = kharghar.new Bill(120);
// compiled roughly as: new Shop$Bill(kharghar, 120)
    javac passes the outer object as a hidden first argument. If kharghar were null, this line would throw NullPointerException.

  3. The link is stored in this$0

    The constructor saves it in the synthetic field final Shop this$0. The Bill object on the heap now points to its Shop object.

  4. Reading an outer field goes through the link

    return name + ": ₹" + amount;   // really: this$0.name + ": ₹" + this.amount
    Each use of an outer field compiles to a read through this$0. If both classes have a field with the same name, write Shop.this.name to mean the outer one.

  5. The link keeps the outer object alive

    As long as any Bill is reachable, its Shop can't be garbage-collected (Lesson 8.3). A long-lived inner object (for example a listener stored in a static list) can therefore leak a large outer object. Static nested classes don't have this problem.

Nested classes in real systems

You use nested classes every day in the JDK and in frameworks, often without noticing the $ in their names.

{{ANIM2}}

1. Data structure internals

HashMap keeps its entries in a static nested class HashMap.Node; LinkedList has LinkedList.Node; ArrayList's iterator is the inner class ArrayList.Itr, which reads the list's private array through its outer link.

list.iterator()→new Itr() (inner)→reads the outer list

2. Builders

Classes with many optional fields often expose a static class Builder nested inside them: new Pizza.Builder().size(LARGE).cheese().build(). The builder is grouped with the class it builds but needs no existing object.

new Order.Builder()→static nested→build() → Order

3. Event handlers and callbacks

Desktop and Android apps attach click listeners as anonymous classes (now usually lambdas). Thread code passes a new Runnable() { … }. Each is a small piece of behaviour written exactly where it's used.

button→new OnClickListener() { … }→runs on tap

4. Memory leaks to watch for

An inner-class listener registered with a long-lived service keeps its outer object (say a whole screen with images) in memory through this$0. Android guidelines recommend static nested classes for such cases.

static registry→inner listener → this$0→outer object can't be freed

A chai stall with bills, tax and a festival offer

interface Offer {
    int apply(int amount);
}

class Stall {
    private final String name;
    private int billCount = 0;

    Stall(String name) { this.name = name; }

    class Bill {                                    // inner: belongs to one stall
        final int no;
        final int amount;

        Bill(int amount) {
            this.amount = amount;
            billCount++;                            // updates the OUTER object's field
            this.no = billCount;
        }

        String print(Offer offer) {
            int pay = offer.apply(amount);
            return name + " #" + no + ": ₹" + pay + " + GST ₹" + Tax.gst(pay);
        }
    }

    static class Tax {                              // static nested: no stall needed
        static int gst(int amount) { return amount * 5 / 100; }
    }
}

public class Main {
    public static void main(String[] args) {
        Stall s = new Stall("Chai Point");
        Offer diwali = new Offer() {                // anonymous class
            public int apply(int amount) { return amount >= 100 ? amount - 20 : amount; }
        };
        Stall.Bill b1 = s.new Bill(120);
        Stall.Bill b2 = s.new Bill(60);
        System.out.println(b1.print(diwali));
        System.out.println(b2.print(diwali));
    }
}

Quick revision

Lesson 10.5 in one screen

  • Nested = class inside a class. Static nested (no outer object) vs inner (member, local, anonymous).
  • Member inner: outer.new Inner(); holds hidden this$0; can read outer private members; Outer.this.x for name clashes.
  • Static nested: new Outer.Nested(); can't use outer instance fields; preferred when no outer object is needed.
  • Local class: inside a method, visible only there.
  • Anonymous: new Interface() { … }; one use; files Outer$1.class. Often replaced by lambdas.
  • Captured locals must be final or effectively final (copied into val$x).
  • Class files: Outer$Inner, Outer$1, Outer$1Local. Inner objects keep outer objects alive.

Interview and viva questions

What is the difference between a static nested class and an inner class?

A static nested class is like a top-level class placed inside another for grouping; it has no reference to an outer object and is created with new Outer.Nested(). An inner class instance is tied to an outer instance (hidden this$0), can use its instance members directly, and is created with outer.new Inner().

Can an inner class access private members of the outer class?

Yes, and the outer class can access the inner class's private members too. Before Java 11, javac generated hidden accessor methods (access$000) for this; since Java 11 the JVM knows they are nestmates and allows it directly.

Anonymous class vs lambda?

A lambda can only implement a functional interface (one abstract method) and has no state of its own; this inside a lambda means the enclosing object. An anonymous class can extend a class, implement several methods, have fields, and its this is the anonymous object itself. Lambdas don't create a $1.class file per use; they're linked at run time (invokedynamic).

Why are captured variables required to be effectively final?

Local variables live on the stack and disappear when the method returns, but the inner object may live longer. So Java copies the value into the object. If the local could change afterwards, the copy would be stale and confusing, so the language forbids changing it.

Can a nested class be private or static? Can a top-level class?

Nested classes can use any access modifier (private, protected, …) and static. Top-level classes can only be public or package-private and can't be static (Lesson 6.5).

Mobile app · memoryJunior

A screen that never leaves memory

After users open and close the “Order history” screen many times, the app runs out of memory. A heap dump shows dozens of screen objects kept alive by a listener list in a singleton service. The listeners are inner classes of the screen. Explain and fix.

The interviewer is checking: the hidden this$0 reference and its effect on GC.

Show a strong answer
  • Each inner listener holds this$0 → the screen. The singleton's list is reachable forever, so every screen (with its views and images) stays reachable.
  • Unregister listeners when the screen closes.
  • Make the listener a static nested class that holds only what it needs (or a weak reference to the screen).
  • Verify with a heap dump before and after.

Avoid: calling System.gc(). The objects are still reachable, so GC can't free them.

Library designFresher

Where should Node live?

You're writing your own LinkedList with a Node class. Should Node be a top-level class, an inner class, or a static nested class?

The interviewer is checking: choosing the right nesting.

Show a strong answer
  • Private static nested: Node is an implementation detail (so nested and private) and doesn't need the list object (so static).
  • An inner Node would waste a this$0 reference per node: memory multiplied by every element.
  • The JDK does exactly this: private static class Node<E> in java.util.LinkedList.

Avoid: making it public top-level “in case someone needs it”. That freezes your internals into your API.

Backend · refactoringJunior

Twenty anonymous comparators

A reporting module sorts lists with 20 copies of new Comparator<Order>() { … }, many identical. How would you clean this up?

The interviewer is checking: when anonymous classes stop being a good idea.

Show a strong answer
  • Replace each with a lambda or Comparator.comparing(Order::getAmount) (Lessons 11.8 and 14.1); one line instead of five.
  • Put reusable rules in one place: static final Comparator<Order> BY_AMOUNT in the Order class.
  • Each anonymous class also generates a separate .class file; fewer, shared comparators are easier to test.

Avoid: leaving duplicated logic because “it works”. Duplicates drift apart over time.

Fintech · APIMid

A payment request with eleven optional fields

The PaymentRequest constructor has 11 parameters, and callers keep mixing up the order of amount and fee. What pattern would you use, and how does nesting help?

The interviewer is checking: the builder pattern with a static nested class.

Show a strong answer
  • A static nested Builder: PaymentRequest.builder().amount(500).fee(5).upi("riya@okbank").build(). Named methods make each value obvious.
  • The builder is nested so it can call the private constructor and stays grouped with the class it builds; it's static because no request exists yet.
  • build() validates required fields, and the resulting object can be immutable.

Avoid: setters on the request itself. A half-filled, mutable payment object is a bug waiting to happen.
