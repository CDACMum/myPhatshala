The dashboard shows 100× revenue

A revenue dashboard suddenly shows a figure about 100 times higher than usual. All pipeline jobs succeeded.

The interviewer is checking: can you debug a data issue systematically?

Show a strong answer
  1. Confirm the symptom and its start date; tell stakeholders you are investigating.
  2. Follow lineage upstream, comparing counts and sums at each layer to find where values change.
  3. Check for schema or unit changes (rupees to paise), duplicates, or join explosions.
  4. Fix the transformation and backfill affected partitions.
  5. Prevent recurrence: range/distribution checks, a data contract with the source team, and alerts.

Avoid: patching the dashboard number by hand.

Security1–3 years

Analysts need customer data, safely

Analysts want access to the customers table, which includes names, phones and addresses.

The interviewer is checking: do you apply least privilege without blocking useful work?

Show a strong answer
  • Classify columns and tag PII in the catalog.
  • Give analysts a view or policy with names removed, phones masked and a pseudonymous customer key for joins.
  • Use row-level filters where teams should see only their region.
  • Keep full access for the few roles that need it, with audit logs and periodic access reviews.
  • Block exports of PII to unmanaged locations.

Avoid: giving everyone full access “just for now”, or refusing access entirely.

Privacy · DPDP1–3 years

Delete one customer from the lake

A customer withdraws consent and asks for erasure. Their data is in raw files, Delta tables, ML features and nightly backups.

The interviewer is checking: do you understand erasure at big data scale?

Show a strong answer

Use the catalog and a pseudonymous key to find all locations. Run row-level deletes on table-format tables (Delta, Iceberg, Hudi), rewrite or expire raw files, vacuum old versions after the retention window, delete derived features and exports, and let immutable backups expire on schedule without restoring erased customers. Record the request and completion. Design ahead: keep PII in few places, separate it from event data, and use keys that make deletion cheap.

Avoid: saying “data lakes are append-only, so we can’t delete”.

Fundamentals · interviewFresher

“What is data governance?”

A common interview and exam question.

The interviewer is checking: can you define it with concrete components and tools?

Show a strong answer

Data governance is the framework of roles, policies and processes that keeps data accurate, understood, secure and used lawfully. Components: ownership and stewardship, a data catalog with business definitions, lineage, classification of sensitive data, quality rules and monitoring, access policies, retention and deletion rules, and compliance with laws such as India’s DPDP Act. Tools include Unity Catalog, Purview, Dataplex, Glue Data Catalog with Lake Formation, DataHub and OpenMetadata.

Avoid: describing governance only as “security”.
