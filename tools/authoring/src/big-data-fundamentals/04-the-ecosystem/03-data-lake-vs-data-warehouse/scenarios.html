Retail · architectureFresher

“Should we put everything in the warehouse?”

A retailer's warehouse holds sales tables. The marketing team now wants to keep website clickstream (JSON), product images and customer chat transcripts “in the warehouse too”.

The interviewer is checking: do you know which data fits which store and why?

Show a strong answer
  • Images and chat transcripts are unstructured; clickstream is high-volume semi-structured JSON. They belong in a lake (object storage), which is far cheaper per TB and accepts any format.
  • Process clickstream into clean, aggregated tables (sessions, conversions) and load those into the warehouse for marketing reports.
  • Catalogue the lake datasets with owners and descriptions from day one.

Avoid: forcing raw JSON and binary files into warehouse tables, or dumping them into the lake with no documentation.

Fintech · reliability1–3 years

The nightly load fails after every app release

Each time the app team adds a field to the payment event, the ETL job loading the warehouse fails and the morning dashboard is empty.

The interviewer is checking: schema evolution and decoupling ingestion from strict schemas.

Show a strong answer
  1. Land raw events in a bronze zone that accepts new fields (schema-on-read), so ingestion never fails.
  2. Build silver and gold with explicit column selection, so new fields are ignored until someone decides to use them.
  3. Use a table format or warehouse feature that supports adding columns safely (schema evolution), and a schema registry or data contract with the app team.
  4. Alert on unexpected schema changes instead of failing silently.

Avoid: asking the app team to stop adding fields, or loosening every column to text.

E-commerce · governance1–3 years

Three numbers for “active customers”

The CEO gets three different “monthly active customers” figures from three teams. Each built its own table from different folders in the lake.

The interviewer is checking: do you recognise a data swamp and know how governance fixes it?

Show a strong answer
  • Agree one business definition (what counts as active, which events, which time zone).
  • Build one certified gold table from silver, with an owner, documentation and tests.
  • Register it in the catalogue with lineage, mark it as the official source, and deprecate the copies.
  • Add data-quality checks (row counts, null rates, freshness) so problems are seen early.

Avoid: picking the number that “looks right” without fixing the definition and ownership.

Telecom · cost and performance3+ years

A query bill that doubled in a month

Analysts query a 400 TB table of call records on a pay-per-scan SQL engine. The bill doubled after a new dashboard went live. The data is stored as CSV in one folder per year.

The interviewer is checking: do you understand file layout, pruning and lakehouse optimisations?

Show a strong answer
  • Rewrite the table as compressed Parquet (or into an Iceberg/Delta table), partitioned by date (and maybe region), so queries read only the needed days and columns.
  • Compact small files and keep file statistics so engines can skip files.
  • Build a small gold aggregate for the dashboard so it never scans raw call records.
  • Set query cost limits and monitor the most expensive queries.

Avoid: only asking analysts to “query less” without fixing the storage layout.
