Retail analytics · correctnessFresher

The national average bill is wrong

Each region computes its average bill value and sends it to head office, which averages the 10 regional averages for the national figure. Finance says the number doesn't match their records.

The interviewer is checking: do you know which results can be combined, and how to combine averages correctly?

Show a strong answer

An average of averages gives every region equal weight, even though regions have very different numbers of bills.

  • Each region should send (total value, number of bills).
  • Head office adds the totals and the counts, then divides once.
  • Medians and distinct counts need similar care: they can't be combined by simple addition either.

Avoid: “weighting by region size” using population or guesses instead of the actual counts.

E-commerce · Spark job1–3 years

199 tasks finish in 2 minutes, one takes 40

A daily job groups orders by seller. The Spark UI shows 199 tasks finishing in about 2 minutes and one task running for 40 minutes. Adding more machines didn't help.

The interviewer is checking: can you recognise data skew and stragglers, and explain why more machines don't fix them?

Show a strong answer

One partition holds far more data than the others, probably a few huge sellers. The job waits for that straggler; extra machines only speed up tasks that were already fast.

  • Check record counts per key to confirm the skew.
  • Split hot keys (add a random “salt” to spread one seller across several partitions, then combine).
  • Pre-aggregate before the big grouping so less data moves.
  • Enable the engine's skew-handling features where available.

Avoid saying: “Just add more nodes.”

Any company · conceptsFresher

“Why not copy all the data to one powerful machine first?”

A teammate suggests copying 50 TB from the cluster to one large server each night to run the report there, “because it's simpler”.

The interviewer is checking: do you understand data locality and network limits, with numbers?

Show a strong answer

At 10 Gbps (about 1.25 GB/s), copying 50 TB takes roughly 11–12 hours of a fully busy link, before any processing, and the single server then hits the walls from Lesson 1.2.

  • Process the data where it lives: run the report as a distributed job on the cluster.
  • Move only the small results (aggregates) to the reporting server or dashboard.
  • Consider processing only the new day's data incrementally.

Avoid: ignoring network transfer time when comparing designs.

Fintech · reliability1–3 years

A worker died at 90% of the job

A 3-hour nightly job runs on 50 workers. At 2 h 40 min, one worker's machine reboots. A junior engineer wants to restart the whole job from the beginning. What should happen instead, and what must the job's code guarantee?

The interviewer is checking: do you know task-level retry and idempotency?

Show a strong answer

Frameworks like Spark and MapReduce re-run only the failed tasks on other nodes using replicated data; finished tasks are not redone. The job finishes a few minutes late, not three hours late.

  • Task output must be idempotent: if a task runs twice, its result is written once (for example, write to a temporary location and commit atomically).
  • Avoid side effects inside tasks (sending emails or payments) that would repeat on retry.
  • For very long pipelines, add checkpoints between stages.

Avoid: designs where a retry double-counts money or sends duplicate notifications.
