Interview · fundamentalsFresher

“Why was Hadoop created?”

An interviewer opens with: “In two minutes, why was Hadoop created and what problem did it solve?”

The interviewer is checking: do you understand the problem behind the tool, not just its name?

Show a strong answer

Around 2003 web-scale data no longer fitted on one machine, and scaling up was too expensive and had a ceiling. Google published GFS and MapReduce, showing how to store data as replicated blocks on many cheap machines and process it in parallel with automatic retries. Hadoop (2006) implemented these ideas as open source: HDFS for storage and MapReduce for processing, later YARN for resource management.

Avoid: listing Hadoop components without saying what problem they solve.

Platform modernisation1–3 years

An old Hadoop cluster and a cloud proposal

Your company runs a 10-year-old on-premises Hadoop cluster with Hive jobs. Leadership asks whether to move to a cloud lakehouse.

The interviewer is checking: can you weigh history, cost and risk instead of following fashion?

Show a strong answer
  • List what runs today: Hive SQL, MapReduce jobs, Spark jobs, downstream reports and their deadlines.
  • Compare total cost: hardware refresh, admin staff and licences versus cloud storage and compute.
  • Check rules: data that must stay in India (choose an Indian cloud region), security and audit needs.
  • Plan in phases: copy data to object storage, convert tables to Parquet/Delta or Iceberg, move Hive SQL to Spark SQL, run both systems in parallel and compare outputs before switching off.

Avoid: “Hadoop is old, so throw it away tomorrow” or “it works, never touch it”.

System design · reasoning1–3 years

Why not just use MapReduce today?

A teammate says, “Spark is just faster MapReduce, so the ideas are the same.” The interviewer asks you to agree or disagree.

The interviewer is checking: do you know what Spark actually changed, and what it kept?

Show a strong answer

Partly agree. Spark keeps the core ideas: partitioned data, parallel tasks, a shuffle for grouping, and re-running failed work. It changed three things: it keeps intermediate data in memory instead of writing to HDFS after every step, it builds a DAG of many steps and optimises the whole plan, and it recovers using lineage instead of replicated intermediate files. It also offers high-level APIs (DataFrames, SQL, streaming, MLlib) instead of hand-written map and reduce functions.

Avoid: saying they are completely different, or that Spark doesn’t need fault tolerance.

Career · learning planFresher

“Should I still learn Hadoop in 2026?”

A junior asks you whether learning Hadoop is a waste of time now that lakehouses exist.

The interviewer is checking: can you give balanced, practical advice?

Show a strong answer

Learn the ideas deeply (HDFS blocks and replication, MapReduce, YARN), because Spark, cloud storage and lakehouses are built on them and interviews still ask them. Spend most hands-on time on Spark, SQL, Kafka, a cloud platform and a table format. Many large Indian enterprises still run Hadoop, so knowing it helps with migration projects.

Avoid: dismissing old tools completely, or spending months on MapReduce Java code.
