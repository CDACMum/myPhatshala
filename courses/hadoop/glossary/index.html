Who's who: Hadoop glossary

Every Hadoop term used in this course in one or two plain sentences, grouped by topic and searchable. Start with Often confused: the pairs of terms that trip up most students and interview candidates. 126 terms so far; the list grows with each module.

Often confused

Block vs input split

A block is how HDFS physically stores bytes (128 MB pieces). An input split is the logical piece one map task reads; it normally matches a block, but a record that crosses a block boundary is read whole by one split.

NameNode vs ResourceManager

Both are masters, of different things. The NameNode manages storage (files and blocks). The ResourceManager manages compute (memory and CPU for jobs).

DataNode vs NodeManager

Both run on a worker. The DataNode stores blocks; the NodeManager runs task containers. Running both on one machine is what makes data locality possible.

Secondary NameNode vs Standby NameNode

The Secondary only merges the edit log into the fsimage. It cannot replace a failed NameNode. The Standby (HA) is a hot spare that takes over automatically.

ResourceManager vs ApplicationMaster

The ResourceManager serves the whole cluster and hands out containers. An ApplicationMaster serves one job and decides which of its tasks run in those containers.

Replication vs backup

Replication keeps live copies to survive hardware failure; deletes and bad writes reach every copy. A backup or snapshot is a separate point-in-time copy you can restore.

Node-local vs rack-local

Node-local: the task runs on a machine holding its block. Rack-local: on another machine in the same rack, so data crosses only the rack switch.

Dead vs stale DataNode

A dead node has been silent past the timeout (≈10.5 min) and its replicas are re-created elsewhere. A stale node has missed heartbeats for a shorter time (30 s by default) and can be avoided for reads and writes without being declared dead.

Standalone vs pseudo-distributed

Standalone runs a job inside one Java process on local files; no daemons. Pseudo-distributed runs every daemon (NameNode, DataNode, ResourceManager…) as a separate process on one machine, with real HDFS and YARN.

core-default.xml vs core-site.xml

core-default.xml holds Hadoop's built-in defaults inside the jars; never edit it. core-site.xml in etc/hadoop is where you override the values you need.

Decommission vs stopping a DataNode

Decommissioning copies every block away first, then marks the node Decommissioned: no moment with fewer replicas. Stopping it is treated as a failure: HDFS waits until the node is declared dead (≈10.5 min) before re-replicating.

hdfs dfs -mv vs -cp

-mv only renames in the NameNode, so it is instant for any size. -cp reads and rewrites every byte through the client (5.6 s vs 1.9 s for 403 MB in our lab).

docker compose stop vs down

stop pauses the containers and keeps their disks, so HDFS data survives. down deletes the containers, and without volumes the data goes with them.

Hardware and clusters

ClusterNetworked nodes that work together as one system. Lesson →
Commodity hardwareOrdinary, affordable servers. Hadoop tolerates their failures in software. Lesson →
Core (spine) switchLarge switch connecting all the racks. Cross-rack traffic goes through it. Lesson →
DaemonA long-running background program. Every Hadoop component (NameNode, DataNode…) is a Java daemon. Lesson →
Edge (gateway) nodeThe node where users log in and submit jobs; runs client tools only. Lesson →
Gateway nodeAnother name for an edge node: client tools and configs, no core daemons. Lesson →
HeartbeatRegular “I am alive” message from a worker to its master. HDFS: every 3 seconds. Lesson →
JBOD“Just a bunch of disks”: separate disks without RAID, the usual choice for DataNodes. Lesson →
Master nodeCoordinates the cluster: keeps metadata, tracks health, assigns work. NameNode, ResourceManager. Lesson →
NodeOne server (or VM) that is a member of a cluster. Lesson →
OversubscriptionWhen a switch's server ports add up to more bandwidth than its uplinks, for example 3 : 1. Lesson →
RackA cabinet of 20–40 servers sharing power and a top-of-rack switch. A failure domain and a bandwidth boundary. Lesson →
ServerA computer built to run all day and serve other computers over a network. Lesson →
Shared-nothingEach node has its own CPU, RAM and disks; nodes share only the network. Lesson →
Single point of failure (SPOF)A part whose failure stops the whole system, such as a master with no standby. Lesson →
ToR switch“Top of rack” switch that connects the servers in one rack and links the rack to the core network. Lesson →
Utility nodeRuns supporting services: ZooKeeper, Hive Metastore, HiveServer2, Oozie, cluster manager. Lesson →
Worker nodeStores data and runs tasks. Usually runs a DataNode and a NodeManager. Lesson →

HDFS

BalancerTool that moves blocks from full DataNodes to emptier ones (hdfs balancer). Lesson →
blk_ and .meta filesA replica on a DataNode disk: blk_N holds the bytes, blk_N_genstamp.meta the checksums (4 B per 512 B). Lesson →
BlockThe unit HDFS stores: a file is cut into blocks of 128 MB by default (the last one can be smaller). Lesson →
Block mapNameNode's in-memory map from each block to the DataNodes holding it; rebuilt from block reports, never saved. Lesson →
Block poolAll blocks of one namespace (BP-…); a folder on every DataNode. Federation gives each NameNode its own. Lesson →
Block reportA DataNode's full list of the blocks on its disks, sent at start-up and periodically. Lesson →
CheckpointMerging fsimage + edit log into a new fsimage (SecondaryNameNode, Standby NameNode or saveNamespace). Lesson →
ChecksumA small value computed from data to detect corruption. HDFS uses CRC32C per 512 bytes. Lesson →
Corrupt replicaA replica whose checksum does not match; the reader reports it (reportBadBlocks) and the NameNode replaces it. Lesson →
DataNodeHDFS worker that stores block replicas on its local disks and serves reads and writes. Lesson →
DecommissioningRetiring a DataNode safely: list it in dfs.hosts.exclude, run -refreshNodes, wait for Decommissioned. Lesson →
dfsadminhdfs dfsadmin: admin client for the NameNode (-report, -refreshNodes, -safemode, -printTopology…). Lesson →
Erasure codingData plus parity cells (for example RS-6-3) instead of full copies: about 1.5× storage. Hadoop 3. Lesson →
FileSystem APIorg.apache.hadoop.fs.FileSystem: the Java API (create, open, listStatus, rename, delete…) used by all Hadoop clients. Lesson →
fs.defaultFSSetting in core-site.xml that tells clients and daemons where the NameNode is, e.g. hdfs://nn1:8020. Lesson →
fsckhdfs fsck path: health report of files and blocks (missing, corrupt, under-replicated); read-only by default. Lesson →
fsimage and edit logThe NameNode's saved metadata: a full snapshot (fsimage) plus a log of every change since (edits). Lesson →
Generation stampVersion number of a block (blk_N_GS); bumped when a pipeline is recovered, so stale replicas can be recognised. Lesson →
getmergehdfs dfs -getmerge dir local.csv: concatenates every file in an HDFS folder into one local file. Lesson →
HDFSHadoop Distributed File System: stores big files as blocks replicated across DataNodes. · later module
hdfs dfsThe HDFS shell (FsShell): Linux-like commands such as -ls, -put, -cat, -mv, -rm on Hadoop file systems. Lesson →
HDFS FederationSeveral independent NameNodes, each managing part of the namespace, sharing the DataNodes. Lesson →
Hedged readIf a read is slow, start a second read on another replica and use whichever finishes first. Lesson →
hflush / hsyncOutput-stream calls: hflush makes written data visible to readers; hsync also forces it to disk on the DataNodes. Lesson →
HttpFSA gateway server offering the WebHDFS API that streams data itself, so clients need to reach only one host. Lesson →
Incremental block reportSmall report of replicas a DataNode received or deleted since its last report. Lesson →
JournalNodes (QJM)An odd-sized group of nodes storing the NameNode edit log, so the standby stays in sync (HA). Lesson →
LeaseA write lock the NameNode gives one client, so only one writer works on a file at a time. Lesson →
Maintenance modePlanned short downtime for a DataNode without copying away all its blocks. Lesson →
Missing blockA block with no live replica at all. Files using it cannot be read. Lesson →
NameNodeThe HDFS master: file names, directories, permissions and the location of every block. Lesson →
Network distanceHops between client and replica in the topology: 0 same node, 2 same rack, 4 other rack. Reads go to the nearest replica. Lesson →
oiv / oevOffline Image Viewer and Offline Edits Viewer: read fsimage and edits files as text/XML. Lesson →
Over-/mis-replicatedOver: more replicas than the target (extras deleted). Mis: enough replicas but all in one rack. Lesson →
PacketA 64 KB piece of a block sent through the write pipeline and acknowledged by every DataNode. Lesson →
PacketUnit of the write pipeline: about 64 KB, i.e. 126 chunks of 512 bytes, each with a 4-byte checksum. Lesson →
Pipeline recoveryWhen a DataNode fails mid-write, the client rebuilds the pipeline with the survivors and a new generation stamp, then keeps writing. Lesson →
Rack awarenessHDFS knowing which rack each node is on (from a topology script), so replicas span racks. Lesson →
Re-replicationMaking new copies of blocks that lost replicas, until each is back to its replication factor. Lesson →
Replication factorHow many copies of each block HDFS keeps. Default 3 (dfs.replication). Lesson →
Safe modeRead-only state of the NameNode at start-up while it waits for enough block reports. Lesson →
Safe mode thresholdint(total blocks × 0.999) must have a reported replica, then a 30 s extension, before safe mode ends. Lesson →
Secondary NameNodeMerges the edit log into the fsimage (checkpointing). It is not a standby and cannot take over. Lesson →
setrephdfs dfs -setrep [-w] N path: change a file's replication factor (and wait). Lesson →
Short-circuit readA client on the same machine reads the block file directly from local disk (dfs.client.read.shortcircuit, off by default). Lesson →
Stale DataNodeNo heartbeat for 30 s: still live, but can be avoided for reads and writes. Lesson →
Standby NameNodeIn High Availability, a second NameNode kept up to date that takes over if the active one fails. · later module
Topology scriptScript named by net.topology.script.file.name that prints a rack for each DataNode IP or host. Lesson →
Transaction ID (txid)Number given to every namespace change in the edit log; fsimage_N contains changes up to N. Lesson →
Trash/user/<name>/.Trash: where -rm moves files when fs.trash.interval > 0 (it is 0, off, by default). Lesson →
triggerBlockReporthdfs dfsadmin -triggerBlockReport host:9867 makes a DataNode send a full block report now. Lesson →
Under-replicated blockA block with fewer live replicas than its replication factor. Lesson →
WebHDFSREST API for HDFS on the NameNode (port 9870); data requests are redirected to DataNodes (port 9864). Lesson →
Write once, read manyHDFS files are written once (and can be appended) but not edited in the middle. Lesson →
Write pipelineThe chain client → DN1 → DN2 → DN3 through which each block is written, with acks flowing back. Lesson →
ZKFCZooKeeper Failover Controller: watches a NameNode and triggers automatic failover in HA. Lesson →

MapReduce

_SUCCESSEmpty file written into a job's output directory when the job completes successfully. Lesson →
CombinerAn optional “mini reducer” run on map output before the shuffle, to send less data. · later module
Data localityRunning a task on, or near, the node that holds its input block. Lesson →
Input splitThe piece of input one map task processes; usually one block, but it is a logical range, not the block itself. Lesson →
JobHistory ServerKeeps logs and counters of finished MapReduce jobs (web UI on port 19888). Lesson →
Mapper / ReducerUser code that turns input records into key–value pairs (map) and combines all values for a key (reduce). · later module
MapReduceProgramming model and engine: map tasks process input splits in parallel, reduce tasks combine the results. · later module
Node-local (data-local)Task runs on a node holding a replica of its input. Network distance 0. Lesson →
Off-rackTask runs in a different rack from its data. Distance 4. Lesson →
Output committerMoves successful task output into the final directory and writes the _SUCCESS marker. Lesson →
Rack-localTask runs on another node in the same rack as its data. Distance 2. Lesson →
RecordReaderTurns a split's bytes into records; finishes a record crossing the split end and skips a partial first line. Lesson →
ShuffleMoving map outputs across the network to the reducers, sorted by key. Lesson →
Speculative executionRunning a backup copy of a slow task elsewhere; the first to finish wins. Lesson →
StragglerA task or node that is alive but much slower than the rest. Lesson →
WaveOne round of tasks when there are more tasks than container slots. Lesson →

YARN

ApplicationMasterOne per job: asks for containers and manages that job's tasks and retries. Lesson →
ContainerA slice of a node's memory and CPU in which one task runs. Lesson →
Delay schedulingWaiting briefly for a slot on a node with the data before running the task elsewhere. Lesson →
NodeManagerYARN worker on each node: launches and monitors containers. Lesson →
ResourceManagerThe YARN master: tracks free resources and grants containers to applications. Lesson →
YARNYet Another Resource Negotiator: Hadoop's cluster resource manager since Hadoop 2. Lesson →

*-site.xmlYour configuration files in etc/hadoop (core, hdfs, yarn, mapred). They override the defaults. Lesson →
-D optionSets a property for one command or job, e.g. hdfs dfs -D dfs.replication=2 -put … Lesson →
/conf and /jmxWeb endpoints of every daemon: the settings in use (with source) and live metrics as JSON. Lesson →
apache/hadoop imageOfficial Docker image of Hadoop; FILE_property=value environment lines become XML settings. Lesson →

Fully distributed modeMasters and workers on separate machines (or containers), replication 3. Production. Lesson →
JAVA_HOMEEnvironment variable pointing to the Java folder (above bin/java). Set it in hadoop-env.sh so every daemon finds Java. Lesson →
NameNode formathdfs namenode -format: creates an empty namespace and a new cluster ID. Once per cluster; again erases HDFS. Lesson →
Passwordless SSHKey-based login without a password; the start scripts use it to start daemons on every host, even localhost. Lesson →
Pseudo-distributed modeEvery daemon on one machine in its own JVM, with HDFS (replication 1) and YARN. For learning. Lesson →
